# Detection note

### How it's detected

The extension inspects only top-level `blob:` pages (every other page is skipped after a one-line check) and blocks one when it both reads like a lock screen (lock wording, "call support", a phone number, an impersonated brand) and tries to trap the user by cancelling escape keys, right-click or leaving, or by forcing full screen or Keyboard Lock. It then disarms the page and replaces it with a warning; a blatant lock screen that opened itself without a click is blocked even without traps.

### Why this approach

Each signal on its own also shows up on legitimate blob pages (editors ask "Leave site?", slideshows go full screen, receipts show phone numbers), but only a scam combines them, which is the same trigger-plus-content pattern Chrome and Edge use.

### False positives

A blob-hosted kiosk or exam app that says "this device is locked" and blocks keys would be blocked, so the warning page offers a session-only "reopen".

### False negatives

It misses lock screens drawn as images or canvas, non-English text, and scams that aren't a top-level blob page, such as iframes or overlays on ordinary sites.

## Extending to related techniques

### Trigger on behaviour, not on the URL

Going full screen, Keyboard Lock, dialog bursts and cancelled escape attempts are cheap to watch on every page, so they can start the content check wherever the deceptive page comes from: an overlay on an ordinary `https:` site, a page generated by a service worker, or a `data:`, `srcdoc` or `about:blank` frame, which would also be scored by how much of the screen it covers.

### Text that isn't in the page

When the lock screen is an image, canvas or video, a screenshot (`chrome.tabs.captureVisibleTab`) read by an on-device OCR or image model would replace text scoring, run only after a trigger so normal browsing stays cheap.

### Other carriers

Picture-in-picture windows, fake browser windows drawn inside a page and fake CAPTCHAs that copy commands to the clipboard fit the same trigger-then-inspect pattern, and the site that generated the blob is itself scannable, so a backend could report it to URL-reputation services.
